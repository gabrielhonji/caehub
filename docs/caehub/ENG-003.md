# ENG-003 — publicação autorizada no GitHub

Use este checklist somente quando a atividade tiver autorização vigente para
push. Ele não transforma commit local em publicação nem autoriza integração,
release ou deploy; essas etapas permanecem separadas conforme ENG-002.

Antes de publicar, confira a raiz do repositório, o estado da árvore, branch, remotos e commits que compõem o incremento. Preserve alterações de outros trabalhos e não inclua arquivos não revisados.

- O remoto oficial do CAEHUB é único e a publicação inicial usa `main`, salvo convenção posterior explícita.
- Revise o `.gitignore` para impedir segredos, credenciais, arquivos `.env`, bancos locais, caches, artefatos de build e logs sensíveis.
- Preserve exemplos de configuração sem segredos, como `.env.example`.
- Execute as verificações pertinentes antes do push e informe falhas sem declarar publicação bem-sucedida.
- Nunca use force push, nem altere o remoto sem conferir seu destino.

Um push só é considerado concluído depois que o GitHub confirmar a atualização da branch esperada.
